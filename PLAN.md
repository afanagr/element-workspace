# План улучшения генерации файлов

Дата: 2026-11-17. База: `main` (`cd0b418`, v2 + обновление OCR/агента).
Статус: предложения зафиксированы, в работу не взяты.

Документ описывает развитие создания файлов (DOCX, XLSX, PDF, PPTX, CSV):
что уже есть, что делать дальше, в каком порядке и по каким критериям
принимать результат. Аудит общих проблем и P0/P1-задач — в
[IMPROVEMENTS.md](IMPROVEMENTS.md); здесь только генерация файлов.

## 1. Базовая линия (что уже работает)

- Инструменты: `write_file`, `edit_file`, `append_file`, `read_file(offset, limit)`,
  `find_nodes`, `excel_read`, `excel_write`, `excel_add_sheet`, `translate_file`,
  `create_pdf`, `convert_to_pdf`, `pdf_split`.
- DOCX (`services/documents.py`): заголовки, абзацы, списки, Markdown-таблицы,
  `**bold**`/`*italic*`/`` `code` ``, fenced code, цитаты, JSON-блоки
  (heading/paragraph/table/list/code/quote/pagebreak/image base64).
- XLSX: типы значений, формулы, жирная шапка, заливка, ширины, freeze, autofilter,
  числовые форматы, объединения, стили, JSON-спецификация листов.
- PDF: DOCX → OnlyOffice `/converter` (подписанная staging-ссылка + JWT) с fallback
  на reportlab; `convert_to_pdf` и `POST /api/nodes/{id}/convert/pdf`.
- После записи файл проверяется read-back-ом; агент имеет бюджет контекста,
  таймауты инструментов и защиту от ложных заявлений о создании.
- Тесты: 59 backend-тестов, `pytest.ini`, `requirements-dev.txt`.

Вывод: дальнейший рост — не «ещё раз переписать текст», а **шаблоны, формальные
схемы, длинные документы, медиа, массовая генерация и UX**.

## 2. Принципы

1. **Детерминизм важнее свободы**: шаблон и схема надёжнее генерации вёрстки токенами.
2. **Проверяемость**: схема → рендер → read-back → отчёт; ошибка возвращается модели.
3. **Экономия контекста**: план → секции → append, а не один огромный tool call.
4. **Безопасность**: без макросов, формула-инъекций, SSRF и внешних картинок по URL.
5. **Обратная совместимость**: Markdown/JSON-режимы и текущие tool-контракты сохраняются.
6. **Пользователь видит результат**: предпросмотр, версия, undo и открытие в OnlyOffice.

## 3. Этапы и задачи

### P0 — первые две недели

#### F1. Шаблоны документов (наибольший эффект)

**Проблема.** Модель каждый раз собирает вёрстку с нуля; юридические документы
получаются разными по оформлению, а сложные стили/колонтитулы недоступны.

**Решение.**
- Хранить эталонные `.docx`/`.xlsx` как обычные файлы проекта (или в библиотеке
  шаблонов администратора) с sidecar-описанием `*.template.json`:
  поля, типы, обязательность, списки строк, подсказки.
- DOCX: плейсхолдеры `{{ field }}`, циклы `{{#items}}…{{/items}}`, условия,
  вставка изображений; предпочтительно `docxtpl` (Jinja2), стили/колонтитулы/
  логотип сохраняются.
- XLSX: именованные ячейки и диапазоны, заполнение строк по списку,
  сохранение формул и форматов.
- Новый инструмент `fill_template(template_node_id, data, output_name, parent_id?)`.
- Валидация `data` по sidecar-схеме до рендера; после записи — read-back и отчёт.
- UI: выбор шаблона при создании файла; «Сохранить как шаблон» из готового файла.

**Критерии готовности.**
- Шаблон претензии/договора с логотипом, колонтитулом и таблицей на 50 строк
  заполняется без потери стилей; файл открывается в Word/OnlyOffice.
- Отсутствующее обязательное поле → понятная ошибка, файл не создаётся.
- DOCX можно сразу конвертировать в PDF через существующий `convert_to_pdf`.

**Оценка:** 2–4 дня. Зависимости: `docxtpl`, sidecar-схема (F2).

#### F2. Формальные схемы и валидация

**Проблема.** JSON-спецификации проверяются ad hoc; ошибки структуры всплывают
уже после генерации, а Markdown-таблицы неоднозначны.

**Решение.**
- Pydantic-модели `DocxSpec`, `XlsxSpec`, `TableSpec`, `ChartSpec`, `ImageSpec`,
  JSON Schema для tool-аргументов.
- Генераторы принимают типизированные спецификации; Markdown остаётся
  совместимым fallback-ом.
- Ошибки валидации возвращаются в tool-result с путём (`blocks[2].table.header`),
  модель исправляет и повторяет.
- Read-back: файл открывается python-docx/openpyxl/pypdf; проверяются
  ожидаемые заголовки/таблицы/листы, отсутствие пустого результата.
- Рядом с файлом сохраняется `*.generation.json` (шаблон, данные, версия
  генератора) для воспроизводимости.

**Критерии готовности.**
- Невалидная схема не создаёт файл и даёт точную ошибку.
- Валидная схема проходит golden-тесты DOCX/XLSX/PDF.
- Пустая таблица/файл без обязательных разделов → `ToolResult(False, …)`.

**Оценка:** 1–2 дня. Делать первым: на этой базе строятся шаблоны и append.

#### F3. Длинные документы без обрыва контекста

**Проблема.** Один `write_file` с целым документом упирается в токены; для
DOCX/XLSX нет структурного добавления (есть только текстовый `append_file`).

**Решение.**
- `append_docx_blocks(node_id, blocks)` — добавлять разделы/таблицы/картинки.
- `append_xlsx_rows(node_id, sheet, rows, start_cell?)` — дописывать данные.
- Генерация по плану: outline → раздел → проверка → следующий раздел.
- Титульный лист, TOC-поле Word, колонтитулы, нумерация страниц, разрывы.
- Лимиты на блоки/строки за вызов; прогресс в UI («раздел 3 из 7»).

**Критерии готовности.**
- 30-страничный DOCX собирается 5–7 вызовами, TOC и колонтитулы на месте.
- XLSX на 10 000 строк дописывается порциями без потери форматов.
- Нет молчаливого обрезания; при лимите — явная ошибка/продолжение.

**Оценка:** 1–2 дня. Зависимости: F2.

### P1 — после P0

#### F4. Изображения, логотипы и графики

**Проблема.** Картинки в DOCX передаются только base64-блоком; графиков нет.

**Решение.**
- Вставка по `node_id` из проекта: `{type:"image", node_id:"…", width_mm:120,
  caption:"…", alt:"…"}`; backend читает blob и вставляет без внешних URL.
- Логотип/водяной знак/подпись/печать — отдельные image-блоки с предупреждением
  о юридической значимости.
- XLSX: нативные диаграммы openpyxl (bar/line/pie/area/scatter), оси, легенда,
  подписи, диапазоны-источники.
- DOCX/PDF: `matplotlib` → PNG → вставка; спецификация `ChartSpec`
  (type, categories, series, title, labels).
- QR-код для реквизитов оплаты, штрихкоды; подписи и нумерация рисунков.

**Критерии готовности.**
- Логотип из проекта вставляется в шапку шаблона без base64 в промпте.
- XLSX с диаграммой открывается в Excel/OnlyOffice, данные совпадают.
- График из таблицы проекта попадает в DOCX и PDF.

**Оценка:** 2–3 дня. Зависимости: F1/F2.

#### F5. PDF-путь: UX и точность

**Проблема.** Серверная конвертация есть, но пользователь не видит кнопок,
предпросмотра и статуса; PDF-формы/PDF/A не поддержаны.

**Решение.**
- Кнопки «Скачать PDF» / «Конвертировать в PDF» в просмотрщике для
  DOCX/XLSX/PPTX; индикатор и ошибка с retry.
- Опция «сделать PDF-версию» при генерации DOCX.
- Предпросмотр PDF до сохранения (iframe/PDF.js или OnlyOffice).
- XLSX/PPTX → PDF через существующий `/converter`; PDF/A и закладки —
  параметры конвертации.
- Заполнение PDF-форм (acroform через pypdf) — отдельная задача.

**Критерии готовности.**
- Из UI можно получить PDF из DOCX/XLSX/PPTX без чата.
- Ошибка DS показывается пользователю, fallback не теряет исходник.
- PDF содержит заголовки/таблицы/изображения исходного DOCX.

**Оценка:** 1–2 дня. Зависимости: F1, `office_convert`.

#### F6. Массовая генерация (mail merge)

**Проблема.** Каждый документ создаётся отдельным запросом; нет массовых
претензий/актов/счетов по таблице.

**Решение.**
- Инструмент `mail_merge(template_node_id, data_node_id, name_pattern,
  output_folder_id?, as_zip=true)`.
- Источник данных: XLSX/CSV; строка → набор полей шаблона.
- Валидация каждой строки; пропуски с причинами; отчёт «создано N, пропущено M».
- ZIP-набор + сводный отчёт; лимиты на количество файлов и размер.
- UI: «Сгенерировать по таблице» с выбором шаблона и колонок.

**Критерии готовности.**
- 50 строк → 50 DOCX в ZIP, имена по шаблону, ошибки по строкам.
- Нет частично созданных «битых» файлов: каждая строка проверена read-back-ом.
- Повторный запуск не дублирует файлы без явного overwrite.

**Оценка:** 2–3 дня. Зависимости: F1, F2.

### P2 — после P1

#### F7. Генерация PPTX

**Решение.** `python-pptx`: титульный слайд, разделы, списки, изображения,
диаграммы, заметки; JSON-спецификация презентации; шаблоны PPTX.
Инструмент `create_pptx`, затем `convert_to_pdf` для PDF-версии.
**Оценка:** 2–3 дня. **Критерий:** 8–12 слайдов с картинками и графиком,
открываются в PowerPoint/OnlyOffice.

#### F8. UX создания файлов

- Диалог «Создать файл»: тип, шаблон, папка, имя, предпросмотр структуры.
- «Сохранить ответ как DOCX/PDF/XLSX» из чата.
- «Открыть в OnlyOffice» сразу после генерации.
- «Перегенерировать раздел» без пересоздания файла.
- Показ плана, использованного шаблона и отчёта валидации.
**Оценка:** 2–3 дня. **Критерий:** пользователь создаёт типовой документ
без ручного ввода tool-аргументов.

#### F9. Качество агентской генерации

- Обязательный план перед мутацией: разделы, данные, таблицы, формат.
- Политика инструментов: `fill_template` → `append_*` → `write_file`;
  PDF — `convert_to_pdf`.
- Калькулятор/проверка сумм и итогов (детерминированно, не «на глаз»).
- Уточняющие вопросы при нехватке реквизитов вместо выдумывания.
- Few-shot примеры для претензии/акта/отчёта; запрет вставлять весь документ
  в чат.
- `*.generation.json` и воспроизводимость; повторная генерация после правок.
**Оценка:** 1–2 дня. **Критерий:** golden-промпты дают ожидаемые tool-call
последовательности и проходят read-back.

#### F10. Sandbox для произвольной вёрстки (advanced)

- Отдельный контейнер без сети, read-only root, tmpfs, non-root, cap-drop,
  лимиты CPU/RAM/pids/времени, без секретов и Docker-сокета.
- Инструмент `run_python(code, output_name)` с `python-docx/openpyxl/reportlab/
  matplotlib`; возврат stdout/stderr и файлов.
- Аудит скрипта в UI, квоты на пользователя; только после F1–F4.
**Оценка:** 3–5 дней + эксплуатация. **Критерий:** генерация документа с
произвольной вёрсткой, попытки сети/чтения чужих файлов блокируются.

#### F11. Надёжность и безопасность

- Защита от формул-инъекций (`=cmd|…`, `HYPERLINK`), макросов, zip-бомб.
- Лимиты: таблицы/строки/изображения/страницы/размер; таймауты и retry.
- Проверка MIME и открытия файла библиотекой; запрет внешних URL для картинок.
- Метрики: время генерации, размер, шаблон/инструмент, причины ошибок.
- Fallback: DS недоступен → reportlab; шаблон сломан → понятная ошибка.

#### F12. Тесты и CI

- Golden-файлы DOCX/XLSX/PDF с проверкой структуры и текста.
- Тесты схем/валидации, append, шаблонов, mail merge, прав доступа.
- UI-smoke создания и конвертации; визуальная проверка ключевых шаблонов.
- GitHub Actions: pytest, ruff, tsc, next build; артефакты тестовых документов.

## 5. Технические решения

### Модули

- `backend/app/services/document_specs.py` — Pydantic-модели и JSON Schema.
- `backend/app/services/templates.py` — поиск шаблонов, sidecar, заполнение.
- `backend/app/services/charts.py` — ChartSpec → openpyxl/matplotlib.
- `backend/app/services/documents.py` — рендер блоков, append, изображения.
- `backend/app/services/tools.py` — новые ToolSpec/обработчики и лимиты.
- `backend/app/services/agent_prompt.py` — политика инструментов и few-shot.
- `frontend/components/ChatPanel.tsx`, `Viewer.tsx`, новый диалог создания —
  выбор шаблона, предпросмотр, «Сохранить как».

### Контракты инструментов (предложение)

```json
{"name": "fill_template",
 "arguments": {"template_node_id": "...", "parent_id": "...",
               "name": "Претензия.docx", "data": {"tenant": "...", "items": []}}}
```

```json
{"name": "append_docx_blocks",
 "arguments": {"node_id": "...", "blocks": [{"type": "heading", "text": "..."}]}}
```

```json
{"name": "append_xlsx_rows",
 "arguments": {"node_id": "...", "sheet": "Лист1", "start_cell": "A100",
               "rows": [["...", 1, "=B2*C2"]]}}
```

```json
{"name": "mail_merge",
 "arguments": {"template_node_id": "...", "data_node_id": "...",
               "name_pattern": "Претензия {{ tenant }}.docx", "as_zip": true}}
```

```json
{"name": "create_pptx",
 "arguments": {"parent_id": "...", "name": "Отчёт.pptx", "slides": []}}
```

### Хранение шаблонов

- Шаблон — обычная файловая нода (DOCX/XLSX/PPTX) + sidecar
  `<имя>.template.json`:
  ```json
  {"kind": "docx", "description": "Претензия",
   "fields": [{"name": "tenant", "type": "string", "required": true}],
   "loop": "items"}
  ```
- Библиотека: папка `.templates` в проекте или отдельный проект администратора.
- Отдельная таблица БД не нужна на MVP; sidecar версионируется вместе с файлом.
- Права: шаблоны видны в рамках проекта; глобальные — только администратор.

### Зависимости

- `docxtpl` — DOCX-шаблоны (Jinja2, циклы, условия, изображения).
- `python-pptx` — PPTX.
- `matplotlib` — графики для DOCX/PDF (тяжёлый; ставить по мере надобности).
- `qrcode` — QR-коды.
- Новые зависимости — отдельным `requirements-generators.txt`, чтобы не
  раздувать базовый образ; при отсутствии — понятная ошибка инструмента.

### Ограничения и конфиг

Предлагаемые настройки: `GENERATED_FILE_MAX_MB`, `MAX_TABLE_ROWS`,
`MAX_DOCX_BLOCKS`, `MAX_IMAGES_PER_DOCUMENT`, `MAIL_MERGE_MAX_FILES`,
`GENERATION_TIMEOUT_SECONDS`, `GENERATION_RECIPE_ENABLED`.
Все лимиты проверяются до рендера, а не после.

### PDF

Новых движков не добавляем: DOCX/XLSX/PPTX → PDF через существующий
`services/office_convert.py` (подписанная staging-ссылка + JWT), fallback —
reportlab. PDF/A и закладки — параметры запроса к DS.

PDF не используется как шаблон: это конечный формат, а не редактируемый макет.
Заполняемые шаблоны — только DOCX/XLSX; результат при необходимости
конвертируется в PDF существующим конвертером. Это надёжнее coordinate-overlay
и не требует отдельного движка разметки PDF.

### Безопасность

- Картинки только из blob-хранилища по `node_id`; внешние URL запрещены.
- Формулы: отклонять/экранировать `=cmd|`, `HYPERLINK`, DDE и подобное.
- Никаких макросов; OOXML проверяется открытием библиотекой.
- Mail merge и sandbox — с квотами и аудитом.
- Секреты и БД недоступны sandbox-контейнеру.

## 6. Definition of Done

Задача считается сделанной, если:

1. Есть Pydantic-схема и валидация входных данных.
2. Генерация проверена read-back-ом (файл открывается, структура не пустая).
3. Ошибки возвращаются модели с путём и не создают «полуфайл».
4. Есть unit/golden-тест и, где нужно, UI-smoke.
5. Обновлены README/PLAN и конфиг/`.env.example`.
6. Нет регрессий текущих Markdown/JSON-режимов и `convert_to_pdf`.

## 7. Метрики

- Доля успешных генераций без ошибок read-back.
- Среднее число tool-вызовов и токенов на один документ.
- Время генерации и конвертации (p50/p95).
- Доля документов, созданных из шаблона.
- Число ручных правок после генерации.
- Для mail merge: создано/пропущено, причины пропусков.

## 8. Риски и меры

| Риск | Мера |
|---|---|
| Шаблоны устаревают/теряют стиль | версия шаблона в sidecar, golden-тесты, предпросмотр |
| `docxtpl`/`python-pptx` раздувают образ | отдельный requirements-файл, ленивая установка/ошибка |
| OnlyOffice перегружен конвертацией | очередь, таймауты, fallback, лимит размера |
| Sandbox = RCE | отдельный контейнер без сети, лимиты, аудит, запрет секретов |
| Формула-инъекции в XLSX | фильтр опасных формул, тесты |
| Юридические документы и печати | предупреждение, ответственность пользователя, без автоподписи |
| Модель выдумывает реквизиты | обязательные поля, уточняющие вопросы, валидация |

## 9. Вне области плана

- Полная совместимость с Word/Excel (поля, VBA, макросы, сложные стили).
- Замена OnlyOffice или собственный офисный движок.
- Улучшение OCR (отдельный трек) и vision-чат.
- Облачные редакторы/совместное редактирование за пределами DS.

## Зафиксированные аксиомы

1. Поддерживаются **любые модели с OpenAI-совместимым API** (`POST {base_url}/chat/completions`,
   SSE, function calling). Никаких «встроенных» провайдеров в коде нет и быть не должно.
2. Модели подключаются **только администратором** в `/admin`: таблица `model_connections`
   (name, base_url, ключ в Fernet, model). Проверено: единственный писатель —
   `services/users.py::sync_connections`, вызывается из `create_user`/`update_user`,
   доступных только через `/api/admin/**` с `current_admin`.
3. Офисные файлы открываются и конвертируются **OnlyOffice Document Server**
   (`OFFICE_EXTENSIONS` в `services/office.py`, `services/office_convert.py`, `api/office.py`).

## P0 — корректность и риски (делать первым)

### 1. В репозитории нет ни одного теста и нет CI
`git ls-files` — 0 файлов `test_*/_test/*.spec`, 0 workflow в `.github`. Любая правка
агента/парсинга проверяется вручную. Минимум:
- `backend/tests/` на `pytest` + `pytest-asyncio`, фикстура с SQLite/Postgres-контейнером;
- «скриптовый» провайдер (`LLMProvider`, который отдаёт заранее заданные `TextDelta`/`ToolCallEvent`)
  — без сети проверяет весь цикл агента;
- golden-набор из 30–50 промптов с ожидаемыми вызовами инструментов;
- `make test` в `Makefile` и GitHub Actions.

Эффект: возможность менять промпт и цикл агента, не ломая поведение.

### 2. Нет бюджета контекста и общего дедлайна
`max_agent_steps=8` (`config.py:47`), `read_file` до 40 000 символов (`tools.py:367`),
tool-результат до 20 000 (`agent.py:589`), история 30 сообщений (`chat_service.py:114`).
Для локальных моделей (8k–32k токенов) это гарантированный обрыв, а 8 шагов × 180 с
таймаут провайдера = до 24 минут на одну задачу.
Сделать: `AgentBudget` (шаги + токены из `usage.prompt_tokens` + `deadline`), окно истории
по токенам, компакция старых ходов в 3–5 строк, `read_file(offset, limit)`.

### 3. Инструменты выполняются последовательно и без таймаута
`agent.py:558-591` — обычный `for` по `tool_calls`; на каждый вызов нет `wait_for`.
Зависшая конвертация OnlyOffice (`onlyoffice_convert_timeout=120`) держит стрим.
Сделать: `asyncio.wait_for(execute_tool(...), settings.tool_timeout_seconds)`; независимые
read-only вызовы запускать параллельно — но **только** с отдельной `AsyncSession` на задачу
(текущий `ToolContext.db` один на весь прогон).

### 4. Нет отмены и нет защиты от петель
`api/chat.py:240-289`: цикл `receive_text` + `run_agent` inline; отключение клиента не
прерывает прогон, «стоп» в UI отправлять нечего. Одинаковый неудачный вызов можно повторять
бесконечно до `max_agent_steps`.
Сделать: кадр `{"type":"cancel"}` + `anyio.CancelScope` вокруг прогона; хеш
`(tool_name, sort_keys(arguments))` и остановка после 2 одинаковых ошибок подряд.

### 5. `translate_file` обрезает документ до 14 000 символов
`tools.py:711`: `source[:14000]`, при этом инструмент отвечает «переведено» — длинные
документы переводятся частично **молча**. Сделать: нарезка по абзацам/строкам таблиц,
несколько вызовов модели, в `summary` — «переведено N из M символов, частей k».

### 6. Нет проверки результата после записи
`write_file`/`excel_write`/`pdf_split` возвращают `ok=True`, даже если получился пустой
файл/0 строк/0 страниц. Сделать: read-back проверка (символы/строки/листы/страницы) и
`ToolResult(False, …)` при несоответствии — это усилит уже существующий анти-«ложный успех»
слой (`agent.py:56-147`).

### 7. Загрузка файлов целиком в память
`api/files.py:121`: `raw = await upload.read()`, лимит 200 МБ × N файлов в одном запросе —
риск OOM при параллельных загрузках. Сделать: потоковая запись (метод `storage.save_stream`
существовал, но не использовался и удалён как мёртвый код — вернуть вместе с
`nodes.create_file_from_path`).

## P1 — качество ответов и функционал

### 8. Намерение пользователя определяется regex-ами
`agent.py:75-155`: только императивы RU/EN («добавь», «создай»), поэтому «Можешь добавить
колонку?», «нужно создать отчёт», «создать/удалить/сделать» (инфинитивы) не распознаются и
коррекция не срабатывает. Сделать: обязательный `plan` (структурированный шаг) перед
мутациями, а regex оставить страховкой; либо классификатор на дешёвой модели.

### 9. Набор инструментов требует полной перезаписи файлов
`write_file` принимает весь контент (`tools.py:445-487`), постраничного чтения нет.
Добавить: `edit_file(node_id, old_text, new_text)` для текстовых форматов,
`append_file`, `find_nodes(query)`, `read_file(offset, limit)`, `excel_read_range`.
Эффект: меньше токенов, меньше обрывов на больших файлах, возможна точечная правка.

### 10. RAG: только dense-поиск без порога и без гибрида
`services/rag.py:66-127` — `top_k=6`, без `score_threshold`, без реранка и BM25; в Qdrant
нет payload-индексов (`vectorstore.py:54-81`), фильтр по `project_id` работает перебором;
при каждом сохранении документ переэмбеддируется целиком (`indexer.py:65-85`).
Сделать: порог score, hybrid (BM25 + вектор, RRF), локальный реранкер, `create_payload_index`
для `project_id`/`node_id`, инкрементальная индексация по хешу содержимого.

### 11. Контекст документов попадает в system-prompt
`agent.py:323-326` вклеивает найденные фрагменты в системное сообщение — это недоверенные
данные (prompt injection из загруженного файла получает «системный» вес). Перенести в
отдельный блок user/tool с маркерами «данные, не инструкции» и правилом игнорировать
инструкции внутри документов.

### 12. Цитаты не валидируются
Модель может сослаться на `[9]`, когда фрагментов 3. Дешёвая проверка после ответа:
номера вне диапазона вырезать/пометить, в событии отдавать `citation_valid`.

### 13. Эмбеддинги жёстко локальные
`factory.resolve_embeddings()` всегда отдаёт `LocalEmbeddingProvider` (MiniLM, 384 dim),
хотя многие OpenAI-совместимые шлюзы умеют `/embeddings`. Сделать тип подключения
«embeddings» (или флаг в `model_connections`) + предупреждение о переиндексации: коллекция
уже пересоздаётся при смене размерности (`vectorstore.py:65-73`), `reindex_all()` есть.

### 14. Vision недоступен
`CompatibleProvider` жёстко ставит `supports_vision=False` (`compatible_provider.py:44-48`),
поэтому сканы идут только через Tesseract. Транспорт для картинок уже написан
(`ChatMessage.images`, `build_user_content` в `openai_provider.py:73-81`).
Добавить «рендер страницы PDF/изображения → `image_url` → vision-модель» с фолбэком на OCR.

### 15. `supports_tools` — мёртвый флаг
`sync_connections` всегда пишет `supports_tools=True` (`services/users.py:169`), в админке
переключателя нет, `/providers/test` не проверяет function calling. Модель без tool calling
ломает агента только в рантайме. Сделать: чекбокс + проба «отправить фиктивный `tools`» и
автометка по тексту ошибки.

### 16. Битый JSON аргументов проглатывается
`llm/schemas.py:148-157`: при `JSONDecodeError` возвращается `{}` → инструмент вызывается
с пустыми аргументами и падает «name is required». Лучше вернуть в tool-результат
«invalid JSON, повтори вызов» — дешёвый self-heal для слабых моделей.

### 17. Ретраи и корпоративные шлюзы
`openai_provider.py:219,264` — фиксированные 0.8/1.6 с, `Retry-After` не учитывается;
`stream_options.include_usage` включается безусловно (часть шлюзов отвечает 400).
Сделать: уважать `Retry-After`, тумблер `stream_options`, `extra_headers`/`api-version`
для корпоративных шлюзов, нормализация `base_url` (дописывать `/v1`) и запрет приватных
адресов в многопользовательском режиме (SSRF через админку).

## Офисные файлы (OnlyOffice) — что заметил при разборе

Проверено: `OFFICE_EXTENSIONS` покрывает docx/odt/rtf/xlsx/xlsm/ods/csv/pptx/odp/pdf;
конфиг редактора подписан JWT, ссылки download/callback — HMAC с TTL и привязкой к
пользователю; сохранение приходит колбэком, создаёт новую версию и ставит файл в индексацию;
`safe_source_url` отсекает публичные хосты и metadata-эндпоинты, разрешая внутренние
docker-имена и приватные адреса. Это соответствует аксиоме «просмотр офисных файлов — OnlyOffice».

Что стоит доработать:

1. **Статус 7 (force save error) теряется.** `api/office.py:118`: `if status not in (2, 6)`
   возвращает `{"error": 0}` без логирования. Пользователь не узнает, что сохранение не прошло.
   Логировать `status=3/7` как warning и пробрасывать ошибку в UI.
2. **`onlyoffice_callback_ttl=86400`.** Редактор, открытый дольше суток, при сохранении получит
   403 «Callback token has expired», и правки потеряются. Продлевать ссылку при `forcesave`
   или увеличить TTL.
3. **CSV теряет формулы.** `spreadsheet_to_csv` читает с `data_only=True`
   (`services/office.py`), т.е. в CSV попадут значения, а формулы — нет. Либо документировать,
   либо хранить CSV как отдельный лист с формулами (ODS).
4. **Асимметрия форматов.** `.rtf/.odt/.ods/.odp` есть в `OFFICE_EXTENSIONS`, но их нет в
   `ALLOWED_UPLOAD_EXTENSIONS` (`services/nodes.py:34-36`) — загрузить такой файл нельзя, хотя
   открыть/редактировать можно. Привести списки в соответствие.
5. **Нет проверки Document Server в `/api/health`.** `office_configured` проверяет только
   заполненность флагов. Добавить `GET {ONLYOFFICE_INTERNAL_URL}/healthcheck` с таймаутом
   2–3 с и отдельный пункт в `checks`.
6. **Размер `documentserver`.** В compose стоит `mem_limit: 3g` и healthcheck — при нехватке
   памяти конвертация падает с 503. Стоит вынести в README рекомендацию (≥4 ГБ RAM у хоста).

- **Кэш зависел только от хеша файла** — после любой правки настроек OCR старые (плохие)

  `OCR_OEM`/`OCR_PSM`, бинаризацию, денойз, рамку, deskew и порог уверенности.
- **Был один PSM 3** — теперь перебираются режимы из `OCR_PSM` (по умолчанию `3,6`), побеждает
  результат с наибольшей средней уверенностью слов (`image_to_data`); `--oem 1` (только LSTM),
  `-c preserve_interword_spaces=1`.
- **Препроцессинг**: апскейл страниц уже 1600 px, медианный денойз, бинаризация Оцу, белая
  рамка 24 px (Tesseract нужны поля вокруг текста).
- **Deskew**: OSD убирает 90/180/270, затем поиск малого наклона по проекционному профилю
  (±`OCR_DESKEW_ANGLE`, по умолчанию 6°).
- **Языковой фолбэк**: при уверенности ниже `OCR_MIN_CONFIDENCE` (55) страница перераспознаётся
  моделью `eng` и берётся лучший результат.
- **Текстовый слой**: страница OCRится, если слой пустой/мусорный (мало букв или много `?`/U+FFFD),
  и такой слой теперь **заменяется** OCR-текстом, а не склеивается с ним (раньше мусор попадал в
  индекс и в ответы агента).
- **Картинки** идут через тот же пайплайн (раньше — голый `image_to_string` без препроцессинга).
- В `meta` появились `ocr_confidence` и `ocr_psm`; `/api/health` отдаёт `checks.ocr`
  (наличие tesseract и установленные языки).
- 11 новых тестов (`backend/tests/test_ocr_quality.py`), всего 59.

Как настраивать: `OCR_DPI=400` для мелкого шрифта; добавить `4` или `11` в `OCR_PSM` для
многоколоночных/разрозненных страниц; `OCR_DESKEW=false`, если выравнивание портит таблицы;
после изменений поднять `OCR_CACHE_VERSION` (иначе старые результаты останутся валидными —
ключ учитывает версию, но не «на глаз»).
